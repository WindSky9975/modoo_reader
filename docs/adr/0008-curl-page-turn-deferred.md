# ADR-0008：仿真翻页延后到 M6，且必须可降级

- 状态：已接受
- 日期：2026-10-31
- 相关：`docs/DEVELOPMENT_PLAN.md` §2.1（翻页动画）、§5（M2/M6）、`packages/ui`

## 背景

「像纸书一样翻页」是最容易被用户注意到的视觉特性，也是性能最贵的一个：整页曲面变形、
阴影与高光、逐帧重建纹理。低端机上极易掉帧（目标 p95 ≤ 16.7ms），而它对「能不能读书」没有帮助。

## 决策

- 翻页动画分三档：**无动画（默认）**、**滑动**、**淡入**，M2 只做这三档。
- 「仿真翻页」排在 M6，且必须满足：可关闭、低端机自动降级、不影响分页器与缓存结构。
- 实现上不允许为了动画把正文渲染成一张大图（会拖垮内存预算 200MB），只能在页级纹理上做文章。

## 后果

**正面**

- M2 的性能预算留给真正影响阅读的部分（分页、预排版、字体测量）。
- 动画与分页解耦，未来换实现不需要动核心。
- 默认无动画，对无障碍与省电都更友好。

**负面**

- 与竞品对比时视觉上不占优势，容易在评测里被扣分。
- M6 才做意味着要等核心稳定后才能评估是否值得做（可能永远不做）。

## 替代方案

| 方案 | 为什么不选 |
| --- | --- |
| M2 就做仿真翻页 | 性能风险集中，且会拖慢分页器上线 |
| 用第三方翻页库 | 多数库自带渲染管线，与自研分页/主题体系冲突 |
| 永久不做 | 保留为可选特性比直接砍掉更稳妥 |

## 复审条件

M2 分页实测在低端机（如 4GB RAM、60Hz）上 p95 仍有 30% 以上余量时，可以提前评估 M6 的仿真翻页。
