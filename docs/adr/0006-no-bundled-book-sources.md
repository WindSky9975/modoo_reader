# ADR-0006：不内置任何书源

- 状态：已接受
- 日期：2026-10-31
- 相关：`docs/DEVELOPMENT_PLAN.md` §8、`README.md` 法律声明、`SECURITY.md`、ADR-0003

## 背景

同类开源阅读器（如 legado）通过社区共享书源获得大量用户，但也因此长期处在版权争议中：
仓库若携带可用的书源规则，等于间接分发「如何抓取正版平台内容」的说明书。
本项目的目标用户是「想安静读自己书的本地读者」，与书城流量模式并不一致。

## 决策

- 仓库**不包含任何可用书源规则**，也不包含针对特定正版站点的抓取代码或测试样本。
- 只提供引擎（ADR-0003）、导入导出能力与文档，规则由用户自行获取与维护。
- 任何「内置书源」或以项目名义分发书源的 PR 直接关闭；Issue 里也不做书源推荐。
- 文档中的示例一律使用 `example.com` 之类的占位域名与虚构结构。

## 后果

**正面**

- 法律风险最低：项目本身是工具，不持有、不分发内容索引。
- 与 MIT 许可证相容，便于商业公司复用引擎部分。
- 项目定位清晰：不做流量生意，因此不需要广告、签到、推荐流。

**负面**

- 开箱即用的书源能力为零，用户必须自己找规则，接受度会低于竞品。
- 社区增长慢：书源是这类项目最主要的传播点，主动放弃意味着放弃这部分流量。
- 维护者要在每个相关 Issue 上重复同一套解释，沟通成本不低。

## 替代方案

| 方案 | 为什么不选 |
| --- | --- |
| 内置少量「示例」书源 | 示例一旦可用就会被当默认使用，风险等同全量内置 |
| 单独开一个「规则仓库」并由本项目链接 | 仍是变相分发，且责任边界模糊 |
| 只支持本地导入，砍掉书源引擎 | 与「可扩展书源插件」的需求冲突，且用户会转向 fork |

## 复审条件

不接受复审。这是项目的法律与品牌底线；若要改变，只能 fork 一个不同的项目。
