# ADR-0007：字体不打包进 APK，走系统字体 + 可选下载

- 状态：待验证（体积）
- 日期：2026-10-31
- 相关：`docs/DEVELOPMENT_PLAN.md` §3.5、`packages/ui` 的 `LayoutSpec.fontFamily/fontVersion`、`THIRD_PARTY.md`

## 背景

中文排版效果与字体强相关，但一套完整中文字体动辄 5–20MB。APK 的体积预算定在 25MB 以内，
把两三套字体打进去就直接超支。另一方面，内置字体的好处是**渲染结果可预测**，分页才能稳定。

## 决策

- **M0–M2 不打包任何字体**，使用系统字体（Android 默认 `Noto Sans CJK`）。
- `LayoutSpec.fontFamily` 记录所选字体族，`fontVersion` 参与 `layoutHash`，
  以便将来引入下载字体时旧缓存自动失效。
- 字体下载能力排在 M5 之后（需要存储管理、许可证提示、断点续传）。
- 一旦引入内置或可下载字体，必须在 `THIRD_PARTY.md` 登记许可证，并在 App 内提供查看入口。

## 后果

**正面**

- APK 体积可控；字体许可证问题延后到真正需要时再解决。
- 依赖系统字体，与用户的系统级字体设置天然一致。

**负面**

- 不同设备字形不同，同一本书的换行位置不同 —— 分页结果不能跨设备复用（本来也不复用，但排障时容易误判）。
- 系统字体缺失生僻字时会回退到别的字体，导致行高抖动、页表不稳。
- 未来「排版高级设置」里想提供「思源宋体」等选项时，需要额外的下载与许可证流程。

## 替代方案

| 方案 | 为什么不选 |
| --- | --- |
| 内置完整中文字体 | 体积直接超预算（+10MB 起） |
| 内置子集化字体 | 子集覆盖不了生僻字；一本书要几千字，子集化收益有限 |
| 全部走系统字体、永不支持自定义 | 与「自定义排版」的需求冲突，用户会拿别的 App 对比 |

## 复审条件

M3 打包实测 APK 体积显著低于预算（例如 < 15MB），且用户对排版一致性有明确诉求时，
可以先内置一套子集字体（仅常用 3500 字 + 标点）验证效果。
